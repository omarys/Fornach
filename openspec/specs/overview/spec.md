## Purpose

OpenSpec provides a tactical turn-based RPG combat and procedural tower dungeon simulation engine
alongside an integrated knowledge documentation and visualization suite (OpenWiki). It simulates
combat mechanics, AI decision-making, procedural dungeon generation, and 2D spatial grid
calculations while supporting headless benchmarking and interactive graph visualization of
documentation.

## Domains

This system is organized into the following domains:

| Domain | Description | Spec |
|--------|-------------|------|
| Fornach-domain | Calculates proportional attribute bonuses as a percentage of current values, guaranteeing minimum scaling thresholds. | [spec.md](../fornach-domain/spec.md) |
| Fornach-engine | Calculates combat strike multipliers, stat axes, net hit damage scaling, defense ratings, and relic hook triggers during combat action resolution. | [spec.md](../fornach-engine/spec.md) |
| Fornach-spatial | Calculates breadth-first distance maps radiating from goal points and determines gradient paths toward or away from goals. | [spec.md](../fornach-spatial/spec.md) |
| Openwiki | Manages documentation page versioning, provenance tracking, and content freshness validation for the repository wiki. | [spec.md](../openwiki/spec.md) |
| Openwiki-visualizer | Provides client-side graphing, styling, filtering, text transformation, and path resolution utilities for the openwiki visualizer. | [spec.md](../openwiki-visualizer/spec.md) |
| Undomained | Automates scheduled and on-demand synchronization of repository documentation using OpenWiki and submits updates as a pull request. | [spec.md](../undomained/spec.md) |

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- Strict separation of 2D spatial grid calculations (fornach-spatial) from gameplay rules and simulation orchestration (fornach-domain, fornach-engine)
- Deterministic simulation design using CombatantId generation to ensure reproducible combat tie-breaking and headless AI benchmarking
- Dual-mode delivery for knowledge visualization supporting both real-time local server hosting (HTTP/SSE) and self-contained static HTML bundle exports
- Domain event segregation via CombatEventService and CombatLogger to decouple combat calculation from diagnostic recording and UI observation
- Use of recursive shadowcasting and discrete grid algorithms (Bresenham, Dijkstra) for deterministic line-of-sight and pathfinding

The system SHALL process data through defined layers:

- **THEN** data flows through: In the game simulation, inputs flow from TowerSession and TowerGenerator through spatial grid computations (fornach-spatial), feeding tactical evaluations and AI decisions into ActionResolver and DicePool, which emit domain events via CombatEventService and state logs via CombatLogger.
