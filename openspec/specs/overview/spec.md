## Purpose

A tactical turn-based CLI roguelike game engine and simulation framework designed for procedural
dungeon exploration, tactical combat, and branching narrative progression. It models complex
multi-attribute combat contests, geometric vision cones, and procedural floor generation while
integrating narrative knots and Monte Carlo combat balancing. It also includes an OpenWiki
visualizer subsystem for exploring documentation graphs and narrative nodes.

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- Isolation of spatial math (A* pathfinding, Dijkstra maps, recursive shadowcasting FOV) into a dedicated fornach-spatial domain independent of combat logic
- Integration with the external Ink narrative engine to separate interactive narrative script authoring from deterministic combat rules
- Headless Monte Carlo combat simulation support (Simulation service) enabling balance benchmarking and automated duel/swarm telemetry without UI dependencies
- Decoupled, event-driven combat side-effects using CombatEventService and equipment trigger hooks rather than hardcoded combatant state mutations
- Spectre.Console terminal presentation layer enforcing consistent color palettes (Dracula theme) and terminal visual effects
- Local filesystem-based persistence for combat logs and diagnostic session streams rather than an external database engine
- Dedicated client-side graph visualizer subsystem (openwiki-visualizer) for rendering project and narrative topology with SSE live-reload

- **THEN** data flows through: User inputs or CLI arguments enter through Program → TowerSession or StoryRunner initiates the run, calling TowerGenerator to create procedural TowerFloor instances → Spatial services (FOV, Pathfinding, Line-of-Sight) calculate visibility and entity movement per turn → Combat actions route through ActionService and ActionResolver, rolling DicePool contests, triggering equipment hooks, and updating Combatant resource pools/meters → CombatEventService emits domain events and results are rendered to the terminal via TowerDisplay/Display (Spectre.Console) → Detailed encounter summaries and debug traces are persisted directly to disk files via CombatLogger and RuntimeLog. ## Technical Notes

- **Architecture Style**: Layered and modular domain-driven architecture. The codebase is organized into distinct domain layers separating CLI terminal presentation, game session and simulation orchestration, spatial geometry/pathfinding algorithms, core combat rules/entities, narrative execution, and an auxiliary web-based documentation visualizer.
- **Security Model**: No authentication or authorization mechanisms are evident in the codebase. The game engine operates as a standalone, single-user CLI application with local disk access. Security measures are limited to the client-side documentation visualizer (VisualizerLib/ClientLib), which applies HTML escaping and path normalization to prevent injection and traversal vulnerabilities when parsing Markdown and graph paths.
- **External Integrations**: Spectre.Console (terminal UI rendering and Dracula theme management), Ink Engine (interactive narrative execution and choice branching), Server-Sent Events / SSE (browser live-reload for OpenWiki visualizer), GitHub Actions (automated workflow for OpenWiki documentation updates), Local Filesystem (disk persistence for combat logs, runtime diagnostic streams, and markdown files)
