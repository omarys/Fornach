# Openwiki-visualizer Specification

> Generated by openlore v1.2.0 on 2026-11-13 21:11

## Purpose

Provides client-side graphing, styling, filtering, text transformation, and path resolution
utilities for the openwiki visualizer.

## Requirements

> `docs/openwiki-visualizer/index.html`

### Requirement: EscapeHtml

The system SHALL the service shall escape html-significant characters (&, <, >, ") to sanitize wiki-sourced strings for dom insertion.

#### Scenario: EscapeDangerousCharacters
- **GIVEN** A string containing characters '&', '<', '>', or '"'
- **WHEN** escapeHtml is called with the string
- **THEN** HTML-significant characters are replaced with corresponding HTML entities

#### Scenario: SafeTextUnchanged
- **GIVEN** A string with plain alphanumeric text
- **WHEN** escapeHtml is called with the string
- **THEN** The string is returned unchanged

### Requirement: ColorsForTypes

The system SHALL the service shall map distinct node types to consistent palette colors based on their order.

#### Scenario: MapNodeTypesToPalette
- **GIVEN** A list of distinct node type names and a color palette
- **WHEN** colorsForTypes is called
- **THEN** A dictionary mapping each node type to a stable palette color is returned

#### Scenario: Valid6DigitHexColor

### Requirement: NodeRadius

The system SHALL the service shall calculate graph node circle radius based on content size and anchor status.

#### Scenario: ComputeRadiusForRegularPage
- **GIVEN** A content size and isAnchor set to false
- **WHEN** nodeRadius is called
- **THEN** The calculated radius is within the defined bounds based on content size

#### Scenario: ComputeRadiusForAnchorPage
- **GIVEN** A content size and isAnchor set to true
- **WHEN** nodeRadius is called
- **THEN** An extra bonus radius is added so the entry page stands out visually

### Requirement: ShouldShowNodeLabel

The system SHALL the service shall determine contextual visibility of node labels based on hover and selection state.

#### Scenario: SelectedNodeOrNeighbor
- **GIVEN** A selected node ID and context indicating the node is selected or in neighborhood
- **WHEN** shouldShowNodeLabel is evaluated
- **THEN** True is returned

#### Scenario: HoveredNodeWithoutSelection
- **GIVEN** No selected node and a matching hovered node ID
- **WHEN** shouldShowNodeLabel is evaluated
- **THEN** True is returned

### Requirement: MatchesFilter

The system SHALL the service shall evaluate whether a node matches the active search query and type filter criteria.

#### Scenario: NodeMatchesSearchQueryAndType
- **GIVEN** A node with matching title/id/tags and matching type filter
- **WHEN** matchesFilter is executed
- **THEN** True is returned for matching criteria

#### Scenario: EmptyFilterInputs
- **GIVEN** An empty query and empty type filter
- **WHEN** matchesFilter is executed
- **THEN** True is returned for any node

### Requirement: Signature

The system SHALL the service shall generate a stable deterministic fingerprint of the graph topology from sorted node ids and directed edges.

#### Scenario: StableGraphTopologySignature
- **GIVEN** A graph object with nodes and edges
- **WHEN** signature is generated
- **THEN** A sorted, delimited string representing node IDs and directed edges is returned

### Requirement: StripFrontmatter

The system SHALL the service shall strip leading yaml frontmatter blocks from markdown text.

#### Scenario: MarkdownWithYAMLFrontmatter
- **GIVEN** A markdown string starting with '---' and followed by a closing '---'
- **WHEN** stripFrontmatter is executed
- **THEN** The frontmatter block is removed and the remaining content is returned

#### Scenario: MarkdownWithoutFrontmatter
- **GIVEN** A markdown string not starting with frontmatter markers
- **WHEN** stripFrontmatter is executed
- **THEN** The body string is returned unchanged

### Requirement: Normalize

The system SHALL the service shall resolve and normalize relative path links against a base directory, collapsing dot segments.

#### Scenario: RelativeLinkWithTraversal
- **GIVEN** A base directory path and a relative path containing '.' and '..' segments
- **WHEN** normalize is executed
- **THEN** Relative segments are collapsed into a canonical wiki path

#### Scenario: ConfigureSimulationForcesAndDimensions
<!-- openlore-test: tags=smoke (auto) -->

- **THEN** selectNode is triggered with the clicked node ID

### Requirement: RenderNode

The system SHALL the visualizer shall paint custom node visuals on the canvas context, applying radial glow highlights for active nodes, type-specific color fills, stroke outlines, and text labels based on zoom thresholds and filter matches.

#### Scenario: RenderActiveHighlightedNodeWithGlow
- **GIVEN** The node is in the active highlight set
- **WHEN** paintNode executes during canvas redraw
- **THEN** A radial gradient glow is drawn around the node followed by the filled node circle and border stroke

#### Scenario: DimNonMatchingNode
- **GIVEN** A search filter is active and the node does not match the filter criteria
- **WHEN** paintNode executes
- **THEN** The node is rendered with reduced opacity

#### Scenario: RenderNodeTextLabel
- **GIVEN** The canvas zoom scale exceeds the visibility threshold or the node is selected
- **WHEN** paintNode completes circle rendering
- **THEN** A text label with background contrast outline is rendered adjacent to the node

### Requirement: RenderPageContent

The system SHALL the visualizer shall sanitize and display wiki page content in the reader pane, stripping yaml frontmatter, converting relative links to visualizer actions, rendering mermaid diagrams, and updating active sidebar state.

#### Scenario: SanitizeAndDisplayMarkdownContent
- **GIVEN** A wiki page containing markdown content and YAML frontmatter
- **WHEN** renderReader is called with the target page ID
- **THEN** Frontmatter is stripped, markup is sanitized via DOMPurify, and rendered into the reader pane

#### Scenario: RenderEmbeddedDiagrams
- **GIVEN** The wiki page markup includes Mermaid diagram blocks
- **WHEN** renderReader processes the rendered container
- **THEN** Mermaid diagram code blocks are evaluated and replaced with interactive SVG diagrams

#### Scenario: SynchronizeSidebarActiveItem
- **GIVEN** The reader successfully renders a wiki page
- **WHEN** renderReader finishes DOM updates
- **THEN** The corresponding sidebar navigation item is marked active and scrolled into view

### Requirement: RewriteDocumentLinks

The system SHALL the visualizer shall intercept internal relative markdown/html links within the reader pane and rewrite them to trigger in-app node selection instead of browser page reloads.

#### Scenario: InterceptInternalWikiAnchorLink
- **GIVEN** An anchor element references a relative markdown file path
- **WHEN** rewriteLinks parses the reader container
- **THEN** Default link navigation is prevented and a click listener is attached that invokes selectNode

#### Scenario: ResolveRelativePathAgainstBaseDirectory
- **GIVEN** An anchor link contains relative path segments including parent directory references
- **WHEN** rewriteLinks resolves the target href
- **THEN** The path is normalized against baseDir to locate the exact target node ID in the graph

### Requirement: SelectNode

The system SHALL the visualizer shall select a specified node by id, calculating immediate neighbor relationships, updating highlighted node and link sets, and triggering reader content updates.

#### Scenario: UpdateNeighborAndEdgeHighlightSets
- **GIVEN** A graph with interconnected nodes
- **WHEN** selectNode is invoked for a given node ID
- **THEN** The target node, its directly connected neighbor nodes, and incident links are added to highlight
sets

#### Scenario: LoadSelectedNodeIntoReader
- **GIVEN** A valid node ID is supplied
- **WHEN** selectNode completes neighborhood graph updates
- **THEN** renderReader is called with the selected node ID

### Requirement: InitializePanelControls

The system SHALL the visualizer shall bind layout controls for resizing and collapsing the graph and reader panels, synchronizing splitter drag interactions and persisting layout preferences in local storage.

#### Scenario: RestorePersistedPanelPreferences
- **GIVEN** Stored layout dimensions or collapsed state exist in localStorage
- **WHEN** initGraphPanelControls runs during initialization
- **THEN** Panel dimensions and toggle states are restored to the persisted configuration

#### Scenario: DragSplitterToAdjustPanelWidth
- **GIVEN** Splitter handle receives drag events
- **WHEN** The user moves the splitter across the window viewport
- **THEN** Panel sizes are updated within bounding constraints and the new width is stored in localStorage
