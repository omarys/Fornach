# Openwiki Specification

> Generated by openlore v1.2.0 on 2026-11-13 21:11
> Source files: docs/openwiki-visualizer/client.js, docs/openwiki-visualizer/client-lib.js

## Purpose

Manages documentation page versioning, provenance tracking, and content freshness validation for the
repository wiki.

## Entities

### Node

> `docs/openwiki-visualizer/client.js`

Represents a wiki document or topic entity rendered within the knowledge graph visualization.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| id | string | Unique identifier for the node, corresponding to the document key or file path. |
| type | string | Classification category of the node used for color assignments and legend filtering. |
| body | string | Markdown body content of the document, containing text and optional YAML frontmatter. |
| isAnchor | boolean | Indicates whether the node acts as a fixed anchor influencing graph layout physics. |
| radius | number | Calculated visual radius for rendering the node arc on the canvas. |

**Relationships:**

- connected-by Link (Connected to adjacent nodes via directional or associative graph links.)
- belongs to WikiGraph (Belongs to the overall wiki knowledge graph structure.)

### Edge

> `docs/openwiki-visualizer/client-lib.js`

Represents a directed link between two wiki nodes in the visualization graph.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| source | string | Identifier of the source node |
| target | string | Identifier of the target node |

**Relationships:**

- originates-from Node (Edge originates from the source Node)
- points-to Node (Edge points to the target Node)

### Graph

> `docs/openwiki-visualizer/client-lib.js`

Represents the entire wiki visualization network topology comprising nodes and directed edges.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| nodes | Node[] | List of all wiki nodes present in the graph |
| edges | Edge[] | List of all directed edges connecting nodes in the graph |

**Relationships:**

- contains Node (Graph contains a collection of nodes)
- contains Edge (Graph contains a collection of directed edges)

### WikiPage

> `docs/openwiki-visualizer/client-lib.js`

Represents the raw content and path resolution context of a wiki document.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| body | string | Markdown body content of the wiki document, which may include frontmatter |
| baseDir | string | Directory path of the page used to resolve relative links |

**Relationships:**

- visualized-as Node (A wiki page maps to a node within the visualization graph)

### Link

> `docs/openwiki-visualizer/client.js`

Represents an edge or relationship between two wiki nodes in the graph visualization.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| source | string | Identifier or reference of the origin node. |
| target | string | Identifier or reference of the destination node. |

**Relationships:**

- connects Node (Connects a source Node to a target Node.)
- belongs to WikiGraph (Belongs to the visualizer graph dataset.)

### WikiGraph

> `docs/openwiki-visualizer/client.js`

Represents the aggregated graph dataset comprising all nodes and links loaded into the visualizer.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| nodes | Node[] | Array of all wiki node entities in the graph. |
| links | Link[] | Array of all relationship links connecting nodes in the graph. |

**Relationships:**

- aggregates Node (Contains and manages the collection of graph nodes.)
- aggregates Link (Contains and manages the collection of graph links.)

## Requirements

### Requirement: NodeValidation

The system SHALL validate Node according to these rules:
- Node identifier must be unique within the graph node registry
- Node body containing frontmatter must be parsable for reader rendering

#### Scenario: SelectNodeToDisplayDetails
- **GIVEN** A rendered force graph containing indexed nodes
- **WHEN** A user clicks or selects a node
- **THEN** Connected neighbor nodes and incident links are highlighted, and the reader panel displays sanitized
markdown content

#### Scenario: FilterNodesByTextMatch
- **GIVEN** An active search query or type filter
- **WHEN** matchesFilter evaluates node properties against the search criteria
- **THEN** Matching nodes remain visible and highlighted while non-matching nodes are dimmed on the canvas and
in the sidebar

### Requirement: EdgeValidation

The system SHALL validate Edge according to these rules:
- Edge must connect a source node identifier to a target node identifier
- Directed edge is formatted as '${source}>${target}' for signature generation

#### Scenario: FormatEdgeSignatureComponent
- **GIVEN** An edge with source 'intro' and target 'quickstart'
- **WHEN** The edge is processed in signature generation
- **THEN** It yields the string representation 'intro>quickstart'

### Requirement: GraphValidation

The system SHALL validate Graph according to these rules:
- Graph topology signature must be computed by joining sorted node IDs with '|' and sorted directed edge strings with '|' separated by '::'

#### Scenario: GenerateGraphTopologyFingerprint
- **GIVEN** A graph with nodes ['b', 'a'] and edges [{source: 'a', target: 'b'}]
- **WHEN** signature(graph) is executed
- **THEN** It returns the stable signature 'a|b::a>b'

#### Scenario: PreserveViewportOnUnchangedTopology
- **GIVEN** A reloaded graph producing an identical signature to the active scene
- **WHEN** The topology is checked against the prior signature
- **THEN** The scene layout and viewport remain intact without resetting

### Requirement: WikiPageValidation

The system SHALL validate WikiPage according to these rules:
- Leading YAML frontmatter starting with '---' and closed by '
---' must be stripped before rendering markdown in the reader
- Relative link navigation paths must collapse '.' and '..' segments into a normalized path

#### Scenario: StripYAMLFrontmatterFromDocument
- **GIVEN** A page body with '--- title: Home --- # Welcome'
- **WHEN** stripFrontmatter(body) is executed
- **THEN** The returned string is '# Welcome'

#### Scenario: PreserveMarkdownContentWithoutFrontmatter
- **GIVEN** A page body '# Documentation'
- **WHEN** stripFrontmatter(body) is executed
- **THEN** The returned string is '# Documentation' unchanged

#### Scenario: ResolveRelativeLinkWithParentTraversal
- **GIVEN** A baseDir 'guides/setup' and relative link '../advanced/config'
- **WHEN** normalize(baseDir, rel) is called
- **THEN** The path resolves to 'guides/advanced/config'

### Requirement: LinkValidation

The system SHALL validate Link according to these rules:
- Source and target node references must resolve to valid nodes in the dataset

#### Scenario: HighlightIncidentLink
- **GIVEN** A link connecting two nodes
- **WHEN** Either endpoint node is selected by the user
- **THEN** The link is marked in highlightLinks and drawn using the active highlight edge color

#### Scenario: DimLinkOnFilterMismatch
- **GIVEN** A graph with an active search filter
- **WHEN** Connected endpoint nodes fail the active filter condition
- **THEN** isLinkDimmed evaluates to true and the link is rendered with dimmed styling

### Requirement: WikiGraphValidation

The system SHALL validate WikiGraph according to these rules:
- All links must reference nodes present within the graph node registry
- Graph dataset must successfully build node lookups without duplicate key collisions

#### Scenario: LoadGraphDataPayload
- **GIVEN** A JSON payload containing nodes and links fetched from the visualizer backend
- **WHEN** load() is executed
- **THEN** Graph data is constructed, colors are assigned by type, sidebar is populated, and ForceGraph engine
initializes

### Requirement: RegisterPage

The system SHALL the system shall register or update a wiki page entry in the manifest, associating the page path with its content version hash, generation run id, authoring model or agent, git commit head sha, and source code fingerprint.

#### Scenario: RegisterNewPageInManifest

fingerprints
- **WHEN** registerPage is called with page metadata
- **THEN** The page entry is stored in the manifest with schemaVersion 1 and corresponding hash records

#### Scenario: UpdateExistingPageInManifest
- **GIVEN** An existing page manifest entry for '/openwiki/combat/fluid-stances.md'
- **WHEN** registerPage is called with updated runId and pageVersion
- **THEN** The manifest entry for the page is updated to reflect the new version while preserving manifest
schema integrity

### Requirement: GetManifest

The system SHALL the system shall retrieve the complete wiki page manifest containing schema version and all registered page metadata entries.

#### Scenario: RetrieveManifestSuccessfully
<!-- openlore-test: tags=smoke (auto) -->

- **WHEN** getManifest is invoked
- **THEN** The full manifest object containing schemaVersion and pages map is returned

### Requirement: VerifyPageFreshness

The system SHALL the system shall verify whether a wiki page is up to date by comparing its recorded sourcefingerprint against the current repository source hash.

#### Scenario: PageIsFresh
- **GIVEN** A registered page whose stored sourceFingerprint matches currentSourceFingerprint
- **WHEN** verifyPageFreshness is called
- **THEN** True is returned indicating the page does not require regeneration

#### Scenario: PageIsStaleDueToSourceDrift
- **GIVEN** A registered page whose stored sourceFingerprint differs from currentSourceFingerprint
- **WHEN** verifyPageFreshness is called
- **THEN** False is returned indicating source code has drifted and documentation must be regenerated

> `openwiki/.last-update.json`

### Requirement: RecordUpdate

The system SHALL the system shall record metadata for a wiki lifecycle execution, including update timestamp, command name, git commit head sha, model identifier, execution status, and documentation language.

#### Scenario: RecordCompletedWikiInit
- **GIVEN** A completed wiki initialization run against Git HEAD 445754965c5690cd25998b097c2bb831b11575e2
- **WHEN** recordUpdate is called with command 'init', status 'complete', and language 'en'
- **THEN** openwiki/.last-update.json is persisted with ISO timestamp and specified metadata

### Requirement: GetUpdateStatus

The system SHALL the system shall read and return the last recorded wiki update state to determine initialization status and target git commit.

#### Scenario: ReadExistingUpdateStatus
- **GIVEN** An existing openwiki/.last-update.json file
- **WHEN** getUpdateStatus is called
- **THEN** The parsed update record containing updatedAt, command, gitHead, model, status, and language is
returned

### Requirement: IsWikiComplete

The system SHALL the system shall evaluate whether the wiki generation completed successfully by inspecting the last update status record.

#### Scenario: WikiStatusComplete
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A last-update record with status 'complete'
- **WHEN** isWikiComplete is evaluated
- **THEN** True is returned indicating wiki generation successfully finished

#### Scenario: WikiStatusInProgressOrFailed
